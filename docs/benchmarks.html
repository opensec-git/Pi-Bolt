Benchmarks

Pi-Bolt 1.0.0 against Pi 1.4.0 as released, run by stock Bun 1.4.4, Node 22 and Node 24, on GitHub's Linux x86-64, Linux ARM64 and Windows runners and an Apple M5 Mac. Lower is better in every row.

How it is measured#

  • The same work for every build. Each build runs the same prompts against a local server that replays the same model responses, so there is no network or provider variance.
  • Pi as released. "Pi on Bun" and "Pi on Node" are Pi 1.4.0 from its npm package (@earendil-works/pi-coding-agent), not Pi-Bolt's tree. Pi-Bolt is the release's code built on its runtimes. Every downloaded build is checked against its checksums.
  • Interleaved. Builds take turns, so a change in the machine's state affects all of them alike. Times to start and sessions are medians of 21 runs.
  • CPU time is user plus system time of the process. Memory is the process's resident memory (on Windows, the working set).

The benchmark scripts, the method in full and the raw data are in the repository: BENCHMARKS.md and bench/results.

PiG starts sooner, streams with less CPU and is a third of the size: it is a native Go program. Pi-Bolt runs Pi's own code, so every Pi extension works unchanged, and over a long session it uses less CPU than PiG. Against Pi-Bolt 0.9.9, CPU per prompt 40 prompts in falls by a third on Linux x86-64 and own memory by 44%, and an answer streaming into a 4,000-entry session takes a tenth of the CPU.

Why a large file write takes so long on stock Pi#

Those two to three minutes are not the disk. A model writes a file by streaming the write tool call's arguments, the whole file, a few characters at a time, so a 400 KB file arrives in thousands of chunks. For every chunk, stock Pi parses the whole tool call again, redraws the screen even when nothing shown has changed, and highlights every line of the file. Each chunk costs more than the last, and the total grows with the square of the file's size. Pi-Bolt parses again only once the arguments have grown by an eighth, draws a frame only when what is shown changes, and highlights only the lines it shows.

In the benchmark the model streams as fast as it can, so the cost shows as wall time. With a real model, which streams more slowly, it shows as CPU.

Why streaming and long sessions cost less#

Streaming. Stock Pi redraws the message every time a few words arrive, and each redraw re-lexes the whole Markdown, re-wraps every block and re-highlights every code block. Pi-Bolt keeps what it has rendered and redoes only the last block or two, with highlighted code cached. The screen shows the same output, line for line.

Long sessions. Every request sends the whole conversation to the model again, and stock Pi serializes all of it from scratch each time, so each prompt costs more than the last. Pi-Bolt builds each request from the previous one's bytes plus what is new. The bytes sent are identical.

Measurements, not guarantees Each table comes from one machine. On other hardware the times differ; what carries over is the comparison.
