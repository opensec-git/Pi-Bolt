Pi-Bolt 1.3.1 is [1.3.0](1.3.0.md) with fixes for grep, resumed sessions, extensions, Herdr and the installer, two
defaults that now follow Pi 1.6.0, and less work for the first answer after launch. Pi is 1.6.0, as in 1.3.0. The engine
is unchanged, so the runtimes are 1.3.0's.

### Changed

- **Two defaults follow Pi 1.6.0**: the `openai`, `azure` and `openai-codex` providers default to GPT-6.2 Sol, and Anthropic
  message threads are on by default for any provider whose `baseUrl` is on `api.anthropic.com`
  (`compat.supportsMessageThreads` turns them off or on for a model). `cacheWarming` stays `"streaming"`, and remote control
  stays off until you turn it on.
- **The first answer after launch** no longer loads the system's Unicode data: text width, truncation and wrapping handle
  emoji between single characters themselves, and text that needs grapheme segmentation is segmented in one call.
- **Syntax highlighting** registers a common language's grammar the first time a code block asks for it. Automatic language
  detection gives the same result whichever grammars were registered first.
- **OpenAI-compatible providers** reuse the client between requests with the same configuration. A changed key or address
  replaces the clients it kept.

### Added

- **Paseo** ([#327](https://github.com/opensec-git/Pi-Bolt/pull/327), by @XelHaku): the shell installer offers to add
  Pi-Bolt as a [Paseo](https://paseo.sh) provider next to Pi when it detects Paseo. `PIBOLT_PASEO=yes` adds it without asking,
  `PIBOLT_PASEO=no` skips it. [Details](https://github.com/opensec-git/Pi-Bolt#paseo)

### Fixed

- **Extensions that draw tool rows themselves** ([#339](https://github.com/opensec-git/Pi-Bolt/issues/339)): a tool row has
  Pi 1.6.0's members again (`hasRendererDefinition()`, `getRenderShell()`, `contentBox`, `contentText`,
  `contentTextRegion`, `selfRenderContainer`, `imageComponents`, `imageSpacers`), so extensions such as `pi-tidy` that
  replace its drawing or mouse handling work, and a click no longer ends with an error. An assistant message's
  `thinkingVisibilityOverrides` is always a map, the `contentContainer` of a streaming answer or of running bash output
  holds the current rows, and the parts of a tool row an extension reads hold the arguments streamed so far.
- **grep never stalls Pi-Bolt** ([#342](https://github.com/opensec-git/Pi-Bolt/issues/342)): a `grep` pattern that
  could backtrack for long on a line, such as several `.*` with alternation over a minified one-line file, is searched with
  ripgrep instead of in-process, found or downloaded as Pi does, and stopping the call stops the search. Without ripgrep,
  the other lines are searched and the result names the lines left out. Other patterns are searched in-process as before,
  with the same results.
- **A session file with a damaged line keeps its history** ([#343](https://github.com/opensec-git/Pi-Bolt/pull/343)): a
  line left unfinished by an interrupted write (a full disk, a killed process) no longer cuts the conversation at that point
  when the session is resumed. An entry whose parent was lost with the damaged line is linked to the entry before it, and the
  next entry is written on a line of its own. Files without damaged lines load as before.
- **Pi's packages in every module of an extension** ([#331](https://github.com/opensec-git/Pi-Bolt/issues/331)): in the
  standalone build, an extension's ES modules, `.cjs` files and `.js` files in `node_modules` that import
  `@earendil-works/pi-*` or `@mariozechner/pi-*` get Pi-Bolt's own packages, not a copy installed next to the extension.
- **Herdr panes that hold another agent's session** ([#330](https://github.com/opensec-git/Pi-Bolt/issues/330)): when Herdr
  does not accept Pi-Bolt's session for a pane, Pi-Bolt reports its state without it and asks again after 10 minutes, instead
  of every report being refused. Herdr gives such a pane to its own Pi integration only; `pi-bolt --herdr-pi` reports as that
  integration. [Troubleshooting](../TROUBLESHOOTING.md)
- **Installing on Alpine and BusyBox** ([#328](https://github.com/opensec-git/Pi-Bolt/issues/328)): the installer unpacks
  a `.tar.xz` only with XZ Utils' `xz` or a `tar` that reads it, and otherwise downloads the `.tar.gz`, checked against the
  signed `SHA256SUMS`. Stopping the installer stops the download and the unpacking and leaves nothing behind.
- **OpenSSL 3 installed as `openssl3`** ([#323](https://github.com/opensec-git/Pi-Bolt/issues/323)), as on AlmaLinux and
  RHEL 8: the installer and `scripts/fetch-runtime.sh` check the release signature with it.
- **Arch Linux** ([#324](https://github.com/opensec-git/Pi-Bolt/issues/324)): the README points to the maintained AUR
  packages `pi-bolt-bin` and `pi-bolt-avx2-bin`.

The macOS interactive CPU figures are from a second set of 24 runs, as that row varied between sets. 1.3.0 and 1.3.1 on Linux
started with `pi-start`.

Against 1.3.0 (medians, n=24): the first answer after launch in the TUI takes 5% fewer instructions and 5% less CPU on macOS
(87.5 → 83.2 M, 17.8 → 16.9 ms) and 11% less CPU on Linux (14.7 → 13.1 ms), with less memory on both. No measured row is
slower than 1.3.0 beyond noise. Seven `grep` calls over `packages/` take the same time in all three versions.

Some rows still cost more than in 1.2.1, as they did in 1.3.0. The first answer over RPC takes about 6% more instructions on
macOS (22.4 → 23.8 M), most of it the newer OpenAI SDK that Pi 1.6.0 brings, loaded at the first request. The TUI's first
answer takes 7% fewer instructions than 1.2.1 on macOS, but 8% more CPU time. Idle CPU after an answer is higher on macOS
(0.58 → 0.68 ms a second; on Linux it is about half of 1.2.1's), and idle memory on Linux is 0.6 MiB higher (13.9 → 14.5 MiB).

### Install

```bash
curl -fsSL https://pi-bolt.opensec.in/install.sh | sh
```

```powershell
irm https://pi-bolt.opensec.in/install.ps1 | iex
```

```bat
powershell -c "irm https://pi-bolt.opensec.in/install.ps1 | iex"
```

or `pi-bolt update`, or `npm install -g --allow-scripts=pi-bolt pi-bolt`, or `bun add -g --trust pi-bolt`, or:

- Homebrew (macOS on Apple silicon, Linux): `brew install opensec-git/tap/pi-bolt`
- Scoop (Windows): `scoop bucket add opensec-git https://github.com/opensec-git/scoop-bucket`, then `scoop install opensec-git/pi-bolt`
- mise: `github:opensec-git/Pi-Bolt` with the options in the [installation guide](https://pi-bolt.opensec.in/docs/installation.html)

The installer checks the release signature with OpenSSL 3, `ssh-keygen` (OpenSSH 8.1 or later), or an installed Pi-Bolt.
Every archive also has a GitHub build attestation: `gh attestation verify <file> -R opensec-git/Pi-Bolt`.
