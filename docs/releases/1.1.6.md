Pi-Bolt 1.1.6 is [1.1.5](1.1.5.md) with Alpine Linux support, native UIs for Pi packages in the phone app, and lower
memory in long sessions. Pi is still 1.5.0. The runtimes are rebuilt for one engine change (#286) and the new musl
runtime.

### Added

- **Alpine Linux and other musl systems (x86-64)** ([#298](https://github.com/opensec-git/Pi-Bolt/pull/298), based on
  the patch set by [@nthrow](https://github.com/nthrow) in [#280](https://github.com/opensec-git/Pi-Bolt/issues/280)):
  - **Builds:** `linux-x64-musl`, `-musl-baseline` and `-musl-jit`, plus the musl runtime and kit.
  - **Installing and updating:** the installer picks musl by itself. `pi-bolt update` and `pi-bolt compile` know the musl
    variants, and the npm launcher picks them on musl.
  - **ICU:** built in with its full data, so `Intl` works with no ICU package installed.
  - **Needs:** `libstdc++`.
- **Native UIs for Pi packages in the phone app** ([#295](https://github.com/opensec-git/Pi-Bolt/pull/295)):
  - **How it works:** an extension describes a view as JSON (cards, lists, key-value, progress, chips, buttons, forms,
    markdown, code, images and more) with `ctx.ui.setView`, `updateView` and `showView`.
  - **Where it shows:** the Pi-Bolt app draws it natively as a panel, an inline card, a page or a sheet. In the
    terminal the same view falls back to widgets, chat lines and dialogs. It works over remote control and RPC.
  - **For authors:** `pi-bolt mobile-ui check` validates a view and `pi-bolt mobile-ui preview` renders it. The
    `pibolt-mobile-ui` skill lets Pi write views for a package. An example package is in
    `examples/extensions/mobile-ui-board`. See [docs/mobile-ui.md](../../packages/coding-agent/docs/mobile-ui.md).

### Changed

- **Less memory in long sessions** ([#293](https://github.com/opensec-git/Pi-Bolt/pull/293)): finished transcript
  entries keep their rendered lines and drop what drew them. A resumed long session rests at 73 MB instead of 88 MB
  (-17%; -14% on `-jit`), with identical screens.
- **One copy of repeated lines** ([#288](https://github.com/opensec-git/Pi-Bolt/pull/288)): short lines that many
  messages draw alike are stored once (-4% at rest).
- **fetch frees the request body early** ([#286](https://github.com/opensec-git/Pi-Bolt/pull/286)): once the response
  starts. Less memory while a large-context answer streams (-2.5%, -5% on `-jit`).

### Fixed

- **Compiled extensions with private names** ([#300](https://github.com/opensec-git/Pi-Bolt/pull/300), from
  [#294](https://github.com/opensec-git/Pi-Bolt/pull/294) by [@silentsokolov](https://github.com/silentsokolov)):
  `pi-bolt compile` no longer rewrites `this.#require()`, `#import()` or `#__dirname`. This had broken extensions such
  as pi-fabric. A private field with one of those names no longer hides a real `require()`.

Also since 1.1.5, outside the release archives:

- **Android app 0.6.1:**
  - package browsing and private registries;
  - live subagents on the phone;
  - the background internet fix.
- **The iOS app (remote control)** is in development under `ios/`.

### Install

```bash
curl -fsSL https://pi-bolt.opensec.in/install.sh | sh
```

```powershell
irm https://pi-bolt.opensec.in/install.ps1 | iex
```

```bat
powershell -c "irm https://pi-bolt.opensec.in/install.ps1 | iex"
```

or `pi-bolt update`, or `npm install -g --allow-scripts=pi-bolt pi-bolt`, or `bun add -g --trust pi-bolt`, or:

- Homebrew (macOS on Apple silicon, Linux): `brew install opensec-git/tap/pi-bolt`
- Scoop (Windows): `scoop bucket add opensec-git https://github.com/opensec-git/scoop-bucket`, then `scoop install opensec-git/pi-bolt`
- mise: `github:opensec-git/Pi-Bolt` with the options in the [installation guide](https://pi-bolt.opensec.in/docs/installation.html)

The installer checks the release signature with OpenSSL 3, `ssh-keygen` (OpenSSH 8.1 or later), or an installed Pi-Bolt.
Every archive also has a GitHub build attestation: `gh attestation verify <file> -R opensec-git/Pi-Bolt`.
