Pi-Bolt 1.3.2 is Pi [1.7.0](https://github.com/earendil-works/pi/releases/tag/v1.7.0) (and
[1.6.1](https://github.com/earendil-works/pi/releases/tag/v1.6.1) before it) on [1.3.1](1.3.1.md), built ahead of time as before,
with an engine that keeps running when many workers are alive. What Pi 1.6.1 and 1.7.0 bring is in their release notes; in short:
program resume in terminals that support it, image generation from codemode, Copilot prompt caching across thinking and tool
changes, bash reporting why its full output could not be saved, and cache-miss notices split into four settings. The engine
changed, so the runtimes are new.

### Changed

- **Pi 1.7.0**: Pi-Bolt's changes are kept on top of it. Defaults follow Pi 1.7.0: the cache-miss notices are four settings
  (`notices.cacheMisses`, `notices.cacheWarming`, `notices.compactionCosts`, `notices.reasoningDrops`), all off, and an existing
  `showCacheMissNotices` is carried over to them; Pi sends no install report; first-time setup asks only about analytics; the
  default models of Mistral, Cloudflare, ant-ling and Qwen Token Plan Individual are the ones Pi 1.7.0 names. `cacheWarming` stays
  `"streaming"`, and remote control stays off until you turn it on.
- **Startup profile**: recorded for Pi 1.7.0, on macOS and Linux, with the prebuilt heap's order on Windows.

### Fixed

- **Many workers at once**: a process with many workers alive (codemode with a high `PI_CODEMODE_MAX_WORKERS`, for example) no
  longer stops at the 14th. Up to 29 realms (the main one and its workers) use the prebuilt heap on Linux and macOS; a worker
  started beyond that runs without it and works as any other.
- **Engine crash reports**: an engine assertion prints its message, and a crash is reported with its report and exit status even
  while a JavaScript listener for `SIGABRT` (or another crash signal) is installed, as `signal-exit` installs one. Such a listener
  still receives the signals other processes send.
- **Workers that compile their own code** no longer crash, rarely, when the process exits.

### Install

```bash
curl -fsSL https://pi-bolt.opensec.in/install.sh | sh
```

```powershell
irm https://pi-bolt.opensec.in/install.ps1 | iex
```

```bat
powershell -c "irm https://pi-bolt.opensec.in/install.ps1 | iex"
```

or `pi-bolt update`, or `npm install -g --allow-scripts=pi-bolt pi-bolt`, or `bun add -g --trust pi-bolt`, or:

- Homebrew (macOS on Apple silicon, Linux): `brew install opensec-git/tap/pi-bolt`
- Scoop (Windows): `scoop bucket add opensec-git https://github.com/opensec-git/scoop-bucket`, then `scoop install opensec-git/pi-bolt`
- mise: `github:opensec-git/Pi-Bolt` with the options in the [installation guide](https://pi-bolt.opensec.in/docs/installation.html)

The installer checks the release signature with OpenSSL 3, `ssh-keygen` (OpenSSH 8.1 or later), or an installed Pi-Bolt.
Every archive also has a GitHub build attestation: `gh attestation verify <file> -R opensec-git/Pi-Bolt`.
