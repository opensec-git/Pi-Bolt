Pi-Bolt 1.2.1 is Pi [1.5.2](https://github.com/earendil-works/pi/releases/tag/v1.5.2) on [1.2.0](1.2.0.md), built ahead of
time as before. What Pi [1.5.1](https://github.com/earendil-works/pi/releases/tag/v1.5.1) and 1.5.2 bring is in their release
notes; in short: `pi-bolt auth login` and `pi-bolt auth logout` from the shell, Anthropic requests that send only the new
messages, richer Mermaid diagrams, Markdown transformers on more surfaces, grep, read and edit that stay small on large files,
Claude Fable 5.2, and a session whose folder was moved or deleted can be forked into the current folder. Everything Pi-Bolt
adds is 1.2.0's. The engine is unchanged, so the runtimes are 1.2.0's.

### Changed

- **Pi 1.5.2** (and 1.5.1 before it): Pi-Bolt's changes are kept on top of it.
- **Prompt cache warming stays as it was.** Pi 1.5.1 makes `"idle"` the default for `cacheWarming`: after each run, Pi
  sends the session's last request again while you are away, for up to 30 minutes, whenever it expects that to save more than
  it costs, and each of those requests is billed. Pi-Bolt keeps `"streaming"`, which keeps caches warm only while a reply is
  being made, as in 1.2.0. To keep caches warm between runs too, set `"cacheWarming": "idle"` in your global settings
  (`~/.pi/agent/settings.json`) or in `/settings`.
- **grep's `glob` is relative to `path`**, in Pi-Bolt's built-in search as with ripgrep: with `path: "repo"`,
  `glob: "src/*.ts"` finds `repo/src/a.ts` and no longer `repo/lib/src/a.ts`; a pattern without `/` matches names at any
  depth. With `context`, lines shared by nearby matches are shown once, and the match limit is reported only when there are
  more matches. Context lines are read from the files a piece at a time, not whole.
- **Startup profile**: recorded again for Pi 1.5.2, on macOS and Linux.
- **Markdown links show where they go** ([#297](https://github.com/opensec-git/Pi-Bolt/issues/297), [#318](https://github.com/opensec-git/Pi-Bolt/pull/318)): a link whose text is not its address shows the address
  in parentheses after the text, and a link to a local file opens on a click in terminals with hyperlinks. Web and mail links
  are clickable text, as before.
- **Updating no longer compiles extensions** ([#317](https://github.com/opensec-git/Pi-Bolt/pull/317)): `pi-bolt update` installs the release's build. Extensions that were
  compiled into the build it replaced load from their files until you run `pi-bolt compile`, which compiles them in again
  with the options of your last compile.
- **npm installs check the npm registry for updates** ([#303](https://github.com/opensec-git/Pi-Bolt/issues/303), [#317](https://github.com/opensec-git/Pi-Bolt/pull/317)): `pi-bolt update` on an npm install asks the npm
  registry for the latest version (`PIBOLT_NPM_REGISTRY` names another), then GitHub, and its hints give the npm command
  that updates or goes back to an earlier version.

### Fixed

- **Downloads try again after a dropped connection** ([#317](https://github.com/opensec-git/Pi-Bolt/pull/317)): the release files `pi-bolt compile` and `pi-bolt update`
  download are tried up to four times after a reset connection, a stall or a server error, going on from where they stopped.
- **A Windows update no longer stops at a locked leftover file** ([#316](https://github.com/opensec-git/Pi-Bolt/issues/316), [#317](https://github.com/opensec-git/Pi-Bolt/pull/317)): a file from an earlier update that a
  running Pi-Bolt still holds is left for a later update instead of ending this one.
- **`pi-bolt compile --off` keeps its record when stopped** ([#317](https://github.com/opensec-git/Pi-Bolt/pull/317)): stopped with Ctrl-C while it downloads, it puts back
  what it records of your last compile.

### Install

```bash
curl -fsSL https://pi-bolt.opensec.in/install.sh | sh
```

```powershell
irm https://pi-bolt.opensec.in/install.ps1 | iex
```

```bat
powershell -c "irm https://pi-bolt.opensec.in/install.ps1 | iex"
```

or `pi-bolt update`, or `npm install -g --allow-scripts=pi-bolt pi-bolt`, or `bun add -g --trust pi-bolt`, or:

- Homebrew (macOS on Apple silicon, Linux): `brew install opensec-git/tap/pi-bolt`
- Scoop (Windows): `scoop bucket add opensec-git https://github.com/opensec-git/scoop-bucket`, then `scoop install opensec-git/pi-bolt`
- mise: `github:opensec-git/Pi-Bolt` with the options in the [installation guide](https://pi-bolt.opensec.in/docs/installation.html)

The installer checks the release signature with OpenSSL 3, `ssh-keygen` (OpenSSH 8.1 or later), or an installed Pi-Bolt.
Every archive also has a GitHub build attestation: `gh attestation verify <file> -R opensec-git/Pi-Bolt`.
