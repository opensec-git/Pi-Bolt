Frequently asked questions

Short answers, with links to the details.

Pi-Bolt and Pi#

Is Pi-Bolt a replacement for Pi, or an add-on?

It is a complete Pi in one executable: you do not need Pi, Node.js or Bun installed. If you have Pi, Pi-Bolt runs next to it as pi-bolt and uses the same configuration, sessions and extensions.

Is it a rewrite of Pi?

No. Pi-Bolt is Pi's own TypeScript source, compiled ahead of time to native code, with a small set of fixes on top. That is why Pi's behavior, commands and extensions carry over. See How it works.

Which version of Pi does it run?

Run pi-bolt --version. The first number is the Pi release the build is made from: 1.4.0 (Pi-Bolt 1.0.0, ...) is Pi 1.4.0.

How quickly does Pi-Bolt follow new Pi releases?

Each new Pi release is merged into Pi-Bolt and released after Pi-Bolt's tests pass. So far that has taken about a day. Run pi-bolt update to get the latest.

Will it change my Pi installation?

No. It installs to its own folder and command. Uninstalling it leaves Pi and ~/.pi/agent in place.

Builds and performance#

Why is the JIT off by default?

Pi is already compiled to machine code, so a JIT would only add compiler threads, warm-up and memory. The JIT only helps code loaded at run time, such as heavy extensions. For those, install the JIT build: it keeps nearly all of Pi-Bolt's gains, within about 5%. See Choose a build.

Why does stock Pi take two minutes to write a 400 KB file?

It is not the disk. The file arrives as a streamed tool call in thousands of small chunks, and stock Pi parses and redraws the whole call for each one, so the work grows with the square of the file's size. Pi-Bolt processes only the new part. See Benchmarks.

Does it make the model faster?

No. The model's speed is the provider's. Pi-Bolt makes everything around it lighter: launching, drawing long answers, handling large tool calls, and long sessions. That matters most on laptops, with several agents at once, and in scripts.

How does it compare with PiG?

PiG, a port of Pi to Go, starts sooner, streams with less CPU and peaks lower in memory; Pi-Bolt runs Pi's own code, so every Pi extension works unchanged, and it uses less CPU deep into a session and writing files in a terminal. See Against PiG.

Extensions and tools#

Do my extensions work?

Yes, unchanged. Extensions that use bun:ffi, such as pi-fff, need the JIT build; opensec-pi-fff gives the same search on the default build. Extensions that start Pi themselves may need to be pointed at pi-bolt. See Extensions.

Does it work with Paseo and other tools that run Pi?

Yes. Set the tool's Pi command to pi-bolt. See Integrations.

Does codemode work?

Yes. Codemode is built into Pi and runs in Pi-Bolt as it does in Pi: pi-bolt -t +codemode.

Platforms#

Which platforms are supported?

Linux on x86-64 or ARM64 with glibc 2.17 or later, macOS 13 or later on Apple silicon, Windows 10 (1809) or later on x64, and Android 7 or later in Termux. See Requirements.

Does it run on Linux ARM64, or on Android?

Yes, both. Linux ARM64 has its own build, for any 64-bit ARM CPU. On Android, run the installer in Termux: it installs Termux's glibc and sets it as the executable's loader. See Android (Termux).

Is it free?

Yes. Pi-Bolt is MIT licensed. Release executables include Bun (MIT), JavaScriptCore (LGPL-2.0 and BSD), ICU and Pi (MIT); see THIRD_PARTY_NOTICES.md.
